# Android signing and upgrades

The testing viewer uses `org.iimg.viewer.rc` and is labeled **IIMG Viewer RC**. The test-source companion uses `org.iimg.handoff.rc` and its own content-provider authority. Both install beside the historical preview apps. The release application ID is `org.iimg.viewer`. Published RC APKs use a development certificate.

Release builds require `IIMG_ANDROID_KEYSTORE`, `IIMG_ANDROID_STORE_PASSWORD`, `IIMG_ANDROID_KEY_ALIAS` and `IIMG_ANDROID_KEY_PASSWORD`. Keep the private keystore and credentials in owner-controlled storage with a tested backup. Preserve the signing identity and increase `versionCode` for updates. The historical preview uses a different development certificate from the local RC build. Users can test the RC alongside that preview through its separate application ID.

Run `:app:assembleRelease` from the Android project after building the release WASM. Verify the APK contents and the certificate fingerprint against the owner's recorded public SHA-256 fingerprint with `scripts/check_android_apk.py` and `scripts/check_android_certificate.py`. Record the exact release tag, APK digest and certificate digest. See the Android SDK verification reference. [Android apksigner](https://developer.android.com/tools/apksigner)

The **Android signed release build** workflow runs against a release tag on `main`. Configure the `iimg-android-signing` environment with a deployment policy restricted to the reviewed release tags and the four environment secrets `IIMG_ANDROID_KEYSTORE_B64`, `IIMG_ANDROID_STORE_PASSWORD`, `IIMG_ANDROID_KEY_ALIAS`, and `IIMG_ANDROID_KEY_PASSWORD`. Set `IIMG_ANDROID_CERT_SHA256` as an environment variable in GitHub's environment settings. The workflow verifies the certificate, removes its temporary keystore file, and attests the APK before uploading it for review. The artifact's APK signature identifies its Android update identity. The GitHub attestation records the build source and workflow. [GitHub artifact attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)

`scripts/test_android_signing.py` exercises the regular release build without credentials and with a disposable signing identity. Its optional emulator procedure re-signs a copy of the prior test APK with the disposable key, installs it, updates to the current build, and checks rejection of a differently signed APK. Supply a fresh test emulator with the base app absent. This exercise validates the update path with test credentials. The owner-signed build and its update test are stable release gates.
