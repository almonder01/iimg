# RFC 0004: finite linear motion

Status: draft under implementation. Required Core 1.0 capability `motion-linear` and critical MOTN chunk, after STAC and before IEND. It requires state-actions/STAC. Legacy readers that do not know MOTN can use their existing unknown-critical static-preview path. No legacy INTR or STAC payload semantics change.

MOTN is an exact JSON object `{ "tracks": [...] }`, at most 32 KiB, with 1–64 tracks. Each track has exact fields `target`, `state`, `equals`, `duration_ms`, `repeat`, `from` and `to`. Targets are unique existing scene objects; state references resolve to STAC; equals is a valid value of that state. Duration is 1–60000 integer milliseconds, repeat is 1–16, and duration*repeat is at most 600000 ms. From/to are `{ "x": u16, "y": u16 }` top-left bounding-box placements, both entirely within the canvas. Geometry size stays fixed. No shape can have two tracks.

The engine clock is an absolute integer logical time from 0 through 86400000 ms. `advance_time` events cannot move backwards; reset starts a new clock at zero. At the clock limit, active tracks settle at their final endpoints and stop requesting frames, including tracks triggered at that limit. Hosts normalize time and pause logical advancement while backgrounded or user-paused. Wall time, scheduling and frame rate are outside the file. Replay validates the entire trace's clock sequence before mutating state. Identical normalized traces give identical frames.

A track is active exactly when its state equals its declared value. On an inactive-to-active transition its origin is the current logical time; remaining active does not restart it. Initially active tracks start at zero. Inactive tracks use original scene positions. For active tracks, interpolate each coordinate as `from + trunc_toward_zero((to-from)*phase/duration)`, using signed integer arithmetic. Before completion phase is elapsed modulo duration; at/after total duration hold the final endpoint. Thus exact boundaries reset between repetitions, while the final boundary holds `to`. The complete validated scene work budget is unchanged by translation.

Reduced-motion preference is an explicit host input. Active tracks immediately use `to` and request no animation frames; inactive tracks still use original geometry. Ordinary Reset preserves this host preference; a replay begins with reduced motion false and may include normalized `motion_preference` events. Visibility and fill still come from STAC. Hit testing uses the current translated geometry; hidden targets remain excluded.

Portable version-1 traces gain exact objects `{ "type":"advance_time", "milliseconds": ... }` and `{ "type":"motion_preference", "reduced": boolean }`. These events require MOTN. New runtime/host APIs must reject invalid clocks without changing state. A host must stop requesting animation frames when complete, unloaded, hidden, paused or reduced-motion; it must clear a scheduled frame when a new file replaces the document. The reference host will expose Pause/Resume for motion and respect prefers-reduced-motion.

Acceptance requires native/Python/WASM frames at initial, midpoint, exact repeat/final boundaries, retrigger and reset, negative-coordinate deltas, reduced-motion input and trace atomicity. Reject invalid ranges/references/placements, duplicate tracks and inconsistent capabilities. Editor/ABI/schema/old-reader fallback and host background/unload cancellation are part of the same increment. No stable-review approval is implied by implementation.
