# RFC 0005: constrained drag values

Status: implemented draft, pending independent review. Core 1.0 required capability `drag-value`, critical DRAG chunk after SCNE/optional ASST/interaction/MOTN and before IEND. It can be used without STAC or INTR. Other readers use unknown-critical static fallback. DRAG is at most 32 KiB and has exact root `{ "sliders": [...] }` with 1–32 entries.

Each entry has exact fields `id`, `target`, `label`, `axis`, `min`, `max`, `step`, `initial`, `from`, `to`. IDs and targets are unique, labels follow Core rules, and targets exist. Axis is x or y. Values are integers with 0<=min<max<=1024, step>=1, step divides max-min and initial-min, and initial is in range. Endpoints are exact x/y top-left placements, fit the canvas, differ along the chosen axis and agree on the other axis. Initial/current placement is `from + trunc_toward_zero((to-from)*(value-min)/(max-min))`. Slider targets cannot also have toggle/state controls or motion tracks; one input and placement owner avoids ambiguous dispatch. State visibility/color bindings may still target them.

Pointer start uses the current topmost visible hit shape and preserves the axis grab offset from its current position. Move clamps the projected offset to the path, quantizes to the nearest step (ties toward increasing value), and updates only that slider. Reverse-axis paths work identically. End commits; cancel restores the value captured at start. Capture is singular. State hiding its target cancels/restores capture. Reset clears capture and restores all declared initial values. A valid direct value set cancels any capture before applying; a hidden target ignores it. Invalid indices/values are rejected without mutation.

Portable traces gain `drag_start`/`drag_move` with existing unsigned canvas-pixel coordinates; `drag_end`/`drag_cancel` without other fields; and `set_slider` with unsigned `index` and `value`. Events require DRAG. Value ranges are prevalidated before replay mutates state. Missed starts or moves/end/cancel without capture are no-ops. Hosts clamp pointer coordinates while captured, track the primary pointer, suppress the synthetic click following a gesture, and cancel on blur/background/unload. A new document must not receive an old gesture. Sliders have real keyboard/accessibility range controls in published order after toggle/state controls, with names/min/max/step/current values; hidden ones are omitted. They do not execute external actions.

Acceptance: native/Python/WASM agree on initial, middle/end, reverse paths, snapping, commit/cancel, direct-value/reset and hidden cancellation. Reject unsupported ranges, missing/duplicate targets, incompatible geometry owners, wrong axis/placements, malformed fields and bad value traces. Test host pointer capture, outside-canvas clamping, click suppression, keyboard range semantics, hidden state, blur/background/unload and editor preservation. Independent/manual review remains a later gate.
