# RFC 0006: raster text authoring and alternative descriptions

Status: implemented draft, pending independent review. This decides the first Core release's text boundary: shaping and font selection happen in the authoring tool. Readers display an existing ASST RGB8 PNG image. They never parse OpenType fonts, fetch resources or accept arbitrary forms. Raster text is portable at the pixel level; glyph output may differ when regenerated on another authoring host. No claim of portable font metrics or editable runtime text is made.

## Source text hints

An authoring asset may contain optional `text` (object or null) with exact fields `text`, `font_family`, `font_size`, `direction`, `color`, `background`. Text is nonempty after Unicode trimming, at most 1024 UTF-8 bytes, at most eight newline-separated lines and has no control characters except LF. Font family is `sans-serif`, `serif` or `monospace`; size is an integer 8–128; direction is `ltr` or `rtl`; colors are RGB triplets. These hints are validated, retained in source JSON and omitted from ASST. The supplied PNG remains authoritative; the compiler does not assert that it matches the hint. Source JSON is a project, not a signed attestation of typography.

The reference editor uses system fonts, explicit direction/alignment and a bounded opaque bitmap of at most 1024×256 pixels that must fit the canvas. Text exceeding its measured line/height box is rejected. RGB8 PNG uses stored DEFLATE blocks with CRC/Adler checksums. Source editing regenerates the bitmap; changing a shared asset affects linked images. It distributes no font files. System fonts and shaping engines affect initial author output; exported PNG pixels remain unchanged in native, WASM and older raster-capable readers. Composition is the browser's native textarea behavior, committed when the author applies the layer. Runtime text input, font licensing/distribution, deterministic shaping, selection and editable form controls require a future profile/RFC, not a silent Core upgrade.

## Optional alternative description

The ancillary `aTXT` chunk has at most 4096 bytes, appears at most once after SCNE and before IEND, and does not change the order of critical chunks. It contains an exact UTF-8 JSON object `{ "description": "…", "language": "ar" }`. Description is nonempty after trimming, at most 2048 UTF-8 bytes and contains no Unicode control characters. Language is a conservative ASCII language-tag subset: a 2–8 letter primary subtag, optional 1–8 alphanumeric subtags separated by single hyphens, at most 35 bytes. Case is retained. This is a syntactic subset, not language registry validation or support for all BCP 47 tags.

The envelope validates CRCs/order/count; full current readers additionally validate the bounded payload. Malformed recognized metadata is rejected. Older readers may ignore ancillary metadata and retain the complete visual/interactive image. No required capability is introduced. Preview-only readers may omit this description when extracting an unsupported document; hosts supply a generic fallback description. Migration preserves recognized aTXT; unknown ancillary chunks are still dropped. The chunk is an untrusted label, never markup/URL/code or a claim of authenticity.

`Runtime::accessibility()` and WASM `describe().accessibility` expose the description and language. The reference viewer places literal description in the canvas accessible name and sets the description/control-group language; unload resets those attributes. A single document language does not solve per-control mixed-language speech. Controls retain their own names, states, ranges, keyboard alternatives and hidden behavior. Authoring provides description/language fields; empty description removes the metadata. Descriptions must explain visual text and interaction purpose; bitmap text alone is not screen-reader text.

## Acceptance and deferred checks

Rust, Python and WASM validate positive Arabic/Latin metadata and reject malformed/oversize/duplicate carriers. Hints cannot alter compiled image bytes. RGB PNG tests independently inflate minimum/maximum multi-block samples and compare complete native/WASM frames. Browser checks author Arabic/Latin, export/reopen exact pixels, re-edit hints, reject overlong input and inertly apply descriptions, including narrow/large-font layout. Older raster-capable engines keep pixels unchanged while ignoring aTXT. Human Arabic typography, IME variants, TalkBack speech and independent accessibility/security review remain explicit release-candidate checks.
